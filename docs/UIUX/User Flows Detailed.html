Part 1

Onboarding & Identity

First-time user journey from app entry through phone authentication to profile creation. Aadhaar eKYC is deferred to the AA consent step.

1.1 — App Entry & Phone Authentication
Phase 1
Entry Points
  • Direct URL visit to finous.site
  • Referral link from another user
  • Bank white-label subdomain (hdfcbank.finous.site)
Exit Points
  • Dashboard (existing user)
  • Profile setup (new user)
  • Abandoned at any step
1
Splash Screen
Finous logo + subtle gold animation. Duration: max 1.5s. Checks for existing valid session.
↓
2
Session exists?
Backend validates refresh token from httpOnly cookie.
Yes → Dashboard
2a
Skip to Home
Route directly to Home — Connected (or Empty State if AA not yet linked).
No → Continue
2b
Welcome Screen
Headline + 2-line sub. CTAs: "Get started" and "I have an account".
↓
3
Phone Entry
+91 country code locked. 10-digit input with auto-format. "Send OTP" button enables once 10 digits valid.
↓
4
OTP Verification
6-digit input. Auto-read OTP on supported browsers. Resend timer 30s. Max 3 attempts.
↓
5
OTP correct?
Backend validates OTP and creates/looks up user.
New user
5a
Name & Email
Name required. Email optional but encouraged. "Continue" advances.
Existing user
5b
Skip to Home
Load profile, refresh AA data if stale, show dashboard.
↓
6
Profile Setup Complete
User lands on Home — Empty State. Next step is "Connect accounts" (AA Consent).
Edge Cases & Error Handling
  • Invalid phone format: inline validation, button stays disabled
  • OTP expired: "OTP expired. Resend a new one." with prominent resend link
  • 3 failed OTP attempts: 15-minute lockout, support contact shown
  • Network failure during OTP send: "Couldn't send OTP. Check your connection and try again."
  • User abandons at OTP screen: session token not created; next visit starts fresh
Part 2

Account Aggregator

The most critical flow in the product. Aadhaar eKYC, AA consent, first data fetch, and consent revocation.

2.1 — First-Time AA Consent & Data Fetch
Phase 2
Entry Points
  • Home — Empty State "Connect accounts" CTA
  • Settings → Linked Accounts → "Add account"
Exit Points
  • Home — Connected (success)
  • Consent Failed screen (failure)
  • User cancels at AA
1
User taps "Connect accounts"
PWA calls backend → AA Module initiates consent flow.
↓
2
Consent Intro Screen
Plain-language explanation: what AA is, what Finous can do, what it can't. One screen, no jargon. CTA: "Proceed to Aadhaar verification".
↓
3
Aadhaar eKYC
12-digit Aadhaar input → OTP sent by UIDAI → 6-digit OTP → verified. Minimal data stored: name, DOB, address.
↓
4
eKYC successful?
Backend confirms with provider.
Yes
4a
Create AA Consent
Backend creates consent artefact via Setu. Duration: 1 year. Purpose: financial dashboard + AI insights.
No
4b
eKYC Failed
Reason shown (invalid Aadhaar / OTP mismatch / provider error). "Retry" and "Contact support" options.
↓
5
Redirect to AA App / Web
User leaves Finous temporarily. AA shows which FIPs to share data from. User approves each institution.
↓
6
User approves consent?
AA sends callback to Finous backend with consent status.
Approved
6a
Fetch FIP Data
Backend pulls data from each FIP via AA. Decrypts using keys from Key Vault. Normalises into standard schema.
Rejected / Cancelled
6b
Consent Declined
"No problem — you can connect accounts whenever you're ready." Return to Home Empty State.
↓
7
Data Normalisation
Financial Data module writes accounts, loans, investments, credit cards to Postgres. Generates Financial Snapshot → Redis (12h TTL).
↓
8
Success Screen — Consent Granted
"Your dashboard is ready." CTA: "View dashboard". Confetti-lite animation. Duration: 2s before auto-forward.
↓
9
Home — Connected
Net worth card, bank balances, EMI burden, credit utilisation, cash flow. First-time tooltip tour overlay (dismissable).
Edge Cases & Error Handling
  • Partial FIP success: If 3 of 4 banks return data, show what's available and flag "SBI data unavailable — retry?"
  • FIP timeout: Retry once after 30s. If still failing, proceed with available data and mark the FIP for background retry.
  • User closes app during AA: Consent remains pending. On next app open, check consent status and resume.
  • Aadhaar locked: UIDAI locks Aadhaar after 3 failed OTP attempts. Show help link to unlock via UIDAI portal.
  • Consent expired before fetch: Rare, but re-create consent and restart from step 5.
2.2 — Consent Revocation (Hard Delete)
Phase 2
Entry Points
  • Settings → Linked Accounts → "Revoke"
  • Settings → Privacy & Data → "Delete my account"
Exit Points
  • Logged out, data deleted
  • Revoked at AA level (single institution)
  • User cancels deletion
1
User taps "Revoke" or "Delete account"
Modal opens with clear consequences: what gets deleted, when, and what's retained.
↓
2
Confirm deletion?
Two-step confirmation required. Type "DELETE" to proceed. Prevents accidental taps.
Confirmed
2a
Block Access Immediately
Session invalidated. All API calls return 401. User logged out.
Cancelled
2b
Return to Settings
No action taken. Modal closed.
↓
3
Deletion Job Triggered
Async job runs. User sees: "Your data will be deleted within 24 hours. Backups clear in 7–14 days."
↓
4
Delete from Live Systems
Postgres rows + Redis cache + Blob objects + Key Vault secrets all removed within 24h.
↓
5
Audit Log Retained
Only hashed user_id, action, timestamp. No financial values. Required for DPDP compliance.
↓
6
Confirmation Email Sent
"Your account and data have been deleted. Backups will clear within 14 days."
Deletion policy commitment: Live systems within 24 hours. Backups within 14 days. This window is documented in the Data Deletion Policy.

Investments: allocation donut. Cards: combined utilisation. Cash Flow: monthly bars.

4
Pull-to-Refresh
User-initiated live data pull. Backend triggers fresh AA fetch for all FIPs. Takes 5–15s. Progress indicator shown.
↓
5
Dashboard Updated
Latest data reflected. Snapshot TTL reset to 12h.
Edge Cases & Error Handling
  • Snapshot missing: Show skeleton loader, trigger fresh AA fetch in background
  • AA consent expired: Home shows "Reconnect your accounts" banner with one-tap renewal
  • Partial data available: Show what's there, flag missing institutions at the top
  • Network offline: Show "You're offline" screen — no cached data displayed
Part 4

AI Advisor & Voice Agent

Conversational AI and voice-first operations. Both enforce "information, not advice" and log anonymised conversations for FLM training.

4.1 — AI Advisor Chat
Phase 2
Entry Points
  • Bottom tab "Ask"
  • Floating "Ask Finous" button on Home
  • Contextual CTA from any feature screen
Exit Points
  • Back to previous screen
  • Switch to Voice mode
  • Start new conversation
1
User opens AI Advisor
Chat screen loads. Greeting: "Hi [name], what would you like to know?" 3 suggested questions shown based on their data.
↓
2
User types or picks a suggestion
Message appears in chat. Backend receives query.
↓
3
AI Service assembles context
Reads Financial Snapshot from Redis. Injects user's real numbers, session tenant, and preferred bank into prompt.
↓
4
LLM call with guardrails
System prompt enforces "information, not advice". Response filtered before return.
↓
5
Response safe?
Post-processing check for recommendation language ("you should", product names, etc.).
Safe
5a
Display Response
Message bubble + disclaimer: "This is general information, not financial or tax advice." Logged for FLM training.
Blocked
5b
Reframe Response
"I can explain how this works, but I can't recommend what you should do. For that, please consult a qualified advisor."
↓
6
Follow-up or Exit
User asks another question, starts new chat, or exits. Conversation stored for 90 days then auto-deleted.
Rate limit: 30 queries per user per day for free tier. Premium tier unlocks unlimited.
4.2 — Voice Agent Session
Phase 2
Entry Points
  • Bottom tab "Ask" → Voice toggle
  • Mic icon on Home
Exit Points
  • End session → transcript view
  • Close app mid-session → lost
  • Token expiry (5 min) → auto-end
1
User taps mic icon
PWA requests short-lived Deepgram token from backend. Voice Module issues 5-min token + creates session record.
↓
2
Mic permission
If first time, browser asks for mic permission. If denied, show fallback text input.
↓
3
Idle → Listening
User speaks. Deepgram STT streams transcript to backend. UI shows pulsing gold ring.
↓
4
Listening → Thinking
Deepgram calls Finous /voice/llm. Same AI Service as chat. Reads Financial Snapshot, assembles prompt.
↓
5
Thinking → Speaking
Deepgram TTS plays response. UI shows waveform animation. User can pause mid-speech.
↓
6
Continue conversation?
User asks another question or ends session.
Continue
6a
Loop back to Listening
Token still valid (5 min TTL). Same session continues.
End session
6b
Post transcript
PWA posts full transcript to backend. Session record closed. Stored for FLM training.
↓
7
Transcript View
Text bubbles like chat. Replay button per response. "Ask another question" or "Done".
Edge Cases & Error Handling
  • App closed mid-session: WebSocket closes. Conversation lost. On reopen: "Session ended. Tap to start a new conversation."
  • Token expires mid-session: Auto-refresh silently if session is active. If refresh fails, session ends gracefully.
  • Deepgram outage: "Voice is unavailable right now. Try text chat instead." Fallback to AI Advisor.
  • Mic permission denied: Show text input option. Explain how to enable in browser settings.
  • Noisy environment: STT confidence low. If repeated, prompt user to type instead.

Tenant Model — Session-Scoped

How tenant routing works (Option B)
1. SubdomainUser opens bank A's white-label app
→
2. GatewayResolves session_tenant = Bank A
→
3. AI AdvisorRoutes recommendations to Bank A's products first
→
4. User SettingsCan pin "preferred bank" — overrides routing only, not branding
One Finous identity, multiple tenant contexts. A user has one account. The tenant they arrive through determines which bank's products get priority in AI recommendations. Users can pin a preferred bank in settings — this affects routing across all apps, but branding always follows the app.

→
2. BackendBlocks all access immediately
→
3. Deletion JobDeletes from Postgres, Redis, Blob within 24h

4. BackupsRetained up to 7–14 days (per Deletion Policy)

Critical Design Notes

Data deletion policy. On revoke, data is removed from the live system within 24 hours. Backup snapshots may retain data for up to 14 days before being overwritten. This window is documented in the Data Deletion Policy and is accepted as compliant under DPDP.
Per-user encryption keys — optional. Since the 7–14 day backup window is accepted, per-user keys are not required for compliance. Recommend keeping them as defense-in-depth — cheap to implement, protects against insider access and misconfigured backups. If deprioritised, document the decision.
AI Service split-ready. The AI module has its own schema, communicates only via internal APIs, and reads context from Redis — not from other modules' databases. It can be deployed as a separate Container App today by changing one line in the deployment manifest.
Voice LLM callback. Deepgram supports "bring your own LLM." Configure the session so Deepgram calls api.finous.site/voice/llm for every turn. This keeps AI logic in one place and enforces "information, not advice" consistently across voice and text.
Data residency. Every Azure service — Postgres, Redis, Blob, Key Vault, Container Apps — must run in Central India. No exceptions. Confirm availability before committing to a service.
Tenant isolation. Every table carries a tenant_id. Every query filters by it. A user's data from Bank A must never leak to Bank B, even if the user is on both. Session tenant is resolved at the gateway and propagated as a header.
Voice session loss. If the user closes the app mid-session, the WebSocket closes and the conversation is lost. The PWA should display: "Session ended. Tap to start a new conversation." No partial transcripts are saved.
